# 503 錯誤修復驗證指南

本指南提供多種方式驗證 503 錯誤修復是否正確應用，無需部署到 Supabase。

## 🔍 驗證方式

### 方式 1: 使用驗證腳本（推薦）

這是最快速的方式，會自動檢查所有修復點。

```bash
cd supabase/functions/line-auth
deno run verify-fixes.ts
```

**檢查項目**:
- ✅ 模組頂層的 `console.warn` 已註釋或移除
- ✅ 環境變數使用 `|| ''` 而非 `!` 斷言
- ✅ `STATE_SECRET` 有條件檢查
- ✅ OPTIONS 請求處理在最前面
- ✅ OPTIONS 返回 200 狀態碼

### 方式 2: 本地功能測試

測試 OPTIONS 請求處理邏輯和環境變數處理。

```bash
cd supabase/functions/line-auth
deno run --allow-net --allow-env test-local.ts
```

**測試內容**:
- OPTIONS 請求處理邏輯
- CORS headers 生成
- 環境變數缺失時的處理
- `STATE_SECRET` 生成邏輯

### 方式 3: 語法檢查

使用 Deno 檢查 TypeScript 語法是否正確。

```bash
cd supabase/functions/line-auth
deno check index.ts
```

### 方式 4: 手動代碼審查

檢查以下關鍵點：

#### ✅ 檢查點 1: 模組頂層 console.warn

**位置**: 文件開頭（第 9-14 行）

**應該看到**:
```typescript
// ⚠️ 關鍵修復：不要在模組載入時執行 console.warn，這可能導致 Edge Function 啟動失敗
// const DISABLE_JWT_VERIFY = Deno.env.get('DISABLE_JWT_VERIFY') === 'true'
// if (DISABLE_JWT_VERIFY) {
//   console.warn('[DIAGNOSTIC] ⚠️ JWT verification is DISABLED for debugging purposes!')
//   console.warn('[DIAGNOSTIC] This should only be enabled in development/testing environments.')
// }
```

**不應該看到**: 未註釋的 `console.warn` 在模組頂層

#### ✅ 檢查點 2: 環境變數處理

**位置**: 第 24-29 行

**應該看到**:
```typescript
const LINE_CHANNEL_ID = Deno.env.get('LINE_CHANNEL_ID')
const LINE_CHANNEL_SECRET = Deno.env.get('LINE_CHANNEL_SECRET')
const SUPABASE_URL = Deno.env.get('SUPABASE_URL') || ''
const SUPABASE_ANON_KEY = Deno.env.get('SUPABASE_ANON_KEY') || ''
const SERVICE_ROLE_KEY = Deno.env.get('SERVICE_ROLE_KEY') || ''
```

**不應該看到**: `Deno.env.get('...')!` （使用 `!` 斷言）

#### ✅ 檢查點 3: STATE_SECRET 生成

**位置**: 第 45 行

**應該看到**:
```typescript
const STATE_SECRET = SERVICE_ROLE_KEY ? SERVICE_ROLE_KEY.substring(0, 32) : 'default-secret-key-for-development-only-32'
```

**不應該看到**: `SERVICE_ROLE_KEY.substring(0, 32)` （沒有條件檢查）

#### ✅ 檢查點 4: OPTIONS 請求處理

**位置**: `Deno.serve` 回調函數開頭（第 132-165 行）

**應該看到**:
```typescript
Deno.serve(async (req) => {
  // ... 日誌 ...
  
  if (req.method === 'OPTIONS') {
    // ... OPTIONS 處理 ...
    return new Response('ok', { 
      headers: corsHeaders,
      status: 200
    })
  }
  
  // ... 其他處理 ...
})
```

**關鍵點**:
- OPTIONS 處理在 `Deno.serve` 回調的最前面
- 返回狀態碼為 200
- 返回內容為 'ok' 字符串

## 📋 驗證清單

在部署前，確認以下所有項目：

- [ ] 運行 `verify-fixes.ts` 所有檢查通過
- [ ] 運行 `test-local.ts` 所有測試通過
- [ ] `deno check index.ts` 無語法錯誤
- [ ] 手動檢查所有檢查點都符合要求

## 🚀 下一步

如果所有驗證都通過：

1. **可以安全部署**: 修復已正確應用，可以部署到 Supabase
2. **部署後測試**: 部署後在 App 中測試 LINE 登入
3. **檢查日誌**: 確認 Supabase Dashboard 日誌中 OPTIONS 請求返回 200

## ⚠️ 如果驗證失敗

如果任何驗證失敗：

1. **檢查錯誤訊息**: 查看具體哪個檢查點失敗
2. **對照修復說明**: 參考 `503錯誤修復說明.md`
3. **重新應用修復**: 根據檢查結果修正代碼
4. **重新驗證**: 再次運行驗證腳本

## 💡 提示

- 驗證腳本可以在任何時候運行，無需 Supabase 環境
- 本地測試可以驗證邏輯正確性，但不能完全模擬 Supabase 環境
- 最終確認仍需要在 Supabase 環境中測試
